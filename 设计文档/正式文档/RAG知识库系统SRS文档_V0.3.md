# 一、引言

## 1.1 目的

本文档旨在详细定义RAG知识库系统的功能需求、性能需求、安全需求和其他非功能需求，为后续的系统设计和开发提供明确的需求基准。

本文档的主要目标包括：

1. **需求明确化**：将业务需求转化为可量化、可测试的系统需求
2. **开发指导**：为开发团队提供清晰的开发依据
3. **验收标准**：为项目验收提供可衡量的评判标准
4. **沟通桥梁**：作为项目干系人之间沟通的基准文档

## 1.2 范围

### 1.2.1 系统范围

本系统是一个基于RAG（Retrieval-Augmented Generation）技术的智能知识库系统，主要包含以下核心功能：

| 功能域 | 功能范围 | 说明 |
|------|---------|------|
| 文档处理 | 多格式文档解析、向量化存储 | 支持PDF、Word、Markdown、TXT等格式 |
| 智能问答 | 语义检索、智能生成 | 基于向量检索和LLM生成 |
| 用户权限 | 认证授权、审计日志 | JWT认证、RBAC权限控制 |
| AI可观测性 | 链路追踪、质量评估 | 全链路监控和评估 |
| 系统管理 | 配置管理、监控告警 | 系统运维支持 |

### 1.2.2 适用对象

| 用户类型 | 角色描述 | 主要使用场景 |
|---------|---------|-------------|
| 知识管理员 | 知识库配置和维护 | 知识库创建、文档管理、权限配置 |
| 普通用户 | 知识检索和问答 | 文档上传、智能问答、知识浏览 |
| 运维人员 | 系统监控和维护 | 监控告警、故障排查、性能优化 |
| 系统管理员 | 系统配置和用户管理 | 用户管理、系统配置 |

### 1.2.3 不在范围内的功能

1. 不支持音视频文件的处理
2. 不支持云端AI服务的集成
3. 不支持多语言翻译功能
4. 不支持复杂的知识图谱构建

# 二、总体描述

## 2.1 产品前景

### 2.1.1 业务背景

随着企业知识的不断积累和数字化转型的深入推进，企业知识管理面临着以下挑战：

| 挑战类型 | 具体表现 | 影响 |
|---------|---------|------|
| 知识分散 | 文档存储在多个系统和文件夹中 | 查找困难，知识利用率低 |
| 检索效率低 | 传统关键词检索无法理解语义 | 难以找到真正相关的文档 |
| 知识孤岛 | 不同部门知识不互通 | 重复工作，创新受限 |
| 知识过时 | 文档更新不同步 | 使用过时信息造成错误 |

### 2.1.2 产品定位

本系统定位为**企业级智能知识管理平台**，具有以下特点：

1. **智能化**：采用RAG技术，实现语义理解和智能问答
2. **私有化**：所有数据存储在客户内网，保证数据安全
3. **可观测**：建立完整的AI链路可观测性体系
4. **易用性**：提供友好的用户界面和流畅的交互体验

### 2.1.3 目标用户

| 用户群体 | 用户规模 | 使用频率 | 核心需求 |
|---------|---------|---------|---------|
| 企业员工 | 50-200人 | 高 | 快速找到答案，提高工作效率 |
| 知识管理员 | 5-10人 | 中 | 便捷管理知识库，监控知识质量 |
| IT运维人员 | 2-5人 | 低 | 系统稳定运行，快速定位问题 |

# 三、具体需求

## 3.1 功能需求

### 3.1.1 用户权限模块

#### 3.1.1.1 用户认证功能

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|---------|--------|---------|
| REQ-UA-001 | 用户注册功能 | P0 | 支持用户名、密码、邮箱注册，密码需加密存储 |
| REQ-UA-002 | 用户登录功能 | P0 | 支持用户名/邮箱+密码登录，返回JWT Token |
| REQ-UA-003 | 用户登出功能 | P1 | 支持Token失效，主动清除会话 |
| REQ-UA-004 | Token刷新功能 | P1 | 支持自动刷新Token，延长会话有效期 |
| REQ-UA-005 | 密码修改功能 | P1 | 支持用户修改自己密码，需验证原密码 |
| REQ-UA-006 | 密码重置功能 | P2 | 支持忘记密码时通过邮箱重置 |

**业务规则：**

1. 用户名长度：4-20个字符，支持字母、数字、下划线
2. 密码强度：至少8位，包含大小写字母和数字
3. Token有效期：Access Token 2小时，Refresh Token 7天
4. 登录失败限制：同一IP连续5次失败，锁定30分钟
5. Token支持动态配置：支持通过配置中心动态调整Token有效期等参数

#### 3.1.1.2 权限管理功能

| 需求ID | 需求描述 | 优先级 | 验收标准 |
|--------|---------|--------|---------|
| REQ-PM-001 | 角色管理 | P1 | 支持角色的增删改查 |
| REQ-PM-002 | 权限分配 | P1 | 支持为角色分配权限 |
| REQ-PM-003 | 用户角色绑定 | P0 | 支持为用户分配角色 |
| REQ-PM-004 | 权限验证 | P0 | API调用时验证用户权限 |
| REQ-PM-005 | 数据权限 | P1 | 支持基于知识库的数据权限控制 |

**角色定义：**

| 角色 | 权限描述 |
|------|---------|
| SYSTEM_ADMIN（系统管理员） | 系统配置、用户管理、角色管理 |
| DEPT_ADMIN（部门管理员） | 本部门管理、用户管理、文档权限配置 |
| DEPT_UPLOADER（部门文档上传者） | 文档上传、自己上传的文档权限配置 |
| DEPT_USER（部门普通人员） | 文档查看（根据权限）、智能问答、个人设置 |

> **说明**：系统采用四角色体系，所有用户必须经过认证，不存在访客角色。

**权限类型定义：**

系统支持四种文档权限类型，用于控制文档的访问范围：

| 权限类型 | 说明 | 适用场景 |
|---------|------|---------|
| COMPANY_WIDE（全公司可见） | 所有用户均可查看 | 公共知识文档 |
| DEPARTMENT_WIDE（部门内可见） | 本部门所有用户可查看 | 部门内部文档 |
| RESTRICTED（指定人员可见） | 最多指定10名用户可查看 | 敏感文档 |
| DEPARTMENT_WIDE_RESTRICTED（部门全员+指定人员） | 本部门全员+其他部门最多10名用户 | 跨部门协作文档 |

> **说明**：RESTRICTED和DEPARTMENT_WIDE_RESTRICTED类型的权限用户数量上限为10人。
