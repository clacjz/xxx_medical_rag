### 9.4 Buffer使用策略

```yaml
预留Buffer：7个工作日

使用原则：
1. 仅在关键任务超期时启用
2. 启用Buffer需要PM批准
3. 每周五评估Buffer使用情况

Buffer分配：
├── LLM部署调优：+2天
├── 性能优化：+2天
├── 测试修复：+2天
└── 应急：+1天

预警机制：
- 当任务延期超过1天时，发出预警
- 当Buffer使用超过50%时，重新评估范围
- 当Buffer使用超过80%时，触发范围调整讨论
```

## 十、风险评估与缓解措施

### 10.1 技术风险

```yaml
┌──────────────────────────────────────────────────────────────────┐
│ 风险1：LLM推理性能不达标                                          │
├──────────────────────────────────────────────────────────────────┤
│ 概率：高（40%）│ 影响：高│ 优先级：P0                          │
├──────────────────────────────────────────────────────────────────┤
│ 描述：                                                          │
│ 本地部署的LLM推理速度可能无法满足10秒响应时间要求                │
│                                                                  │
│ 风险因素：                                                        │
│ • GPU显存限制                                                    │
│ • 模型量化损失                                                   │
│ • 并发请求处理                                                   │
│                                                                  │
│ 缓解措施：                                                        │
│ 1. 预留2天Buffer专门处理LLM优化                                  │
│ 2. 选择量化模型（GPTQ/GGUF）减少显存占用                         │
│ 3. 准备多个LLM方案（Ollama/vLLM/llama.cpp）                     │
│ 4. 实现请求队列和超时机制                                        │
│ 5. 考虑流式输出改善用户体验                                      │
│                                                                  │
│ 触发条件：                                                       │
│ 如果LLM首次调用超过30秒，立即启动优化方案                        │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│ 风险2：文档处理质量不达标                                        │
├──────────────────────────────────────────────────────────────────┤
│ 概率：中（30%）│ 影响：中│ 优先级：P1                          │
├──────────────────────────────────────────────────────────────────┤
│ 描述：                                                          │
│ 复杂PDF（如扫描件、表格密集型）解析效果可能不佳                   │
│                                                                  │
│ 缓解措施：                                                        │
│ 1. 提前进行多种PDF测试                                           │
│ 2. 集成PaddleOCR作为补充                                         │
│ 3. 提供人工标注接口处理异常文档                                   │
│ 4. 分块质量评估机制                                              │
│                                                                  │
│ 触发条件：                                                       │
│ 如果表格提取准确率<80%，启用OCR增强                              │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│ 风险3：Embedding检索效果不佳                                     │
├──────────────────────────────────────────────────────────────────┤
│ 概率：低（20%）│ 影响：中│ 优先级：P1                          │
├──────────────────────────────────────────────────────────────────┤
│ 描述：                                                          │
│ 向量检索可能无法召回正确答案，影响RAG效果                        │
│                                                                  │
│ 缓解措施：                                                        │
│ 1. 使用BGE-large-zh-v1.5（中文优化）                            │
│ 2. 实现混合检索策略（向量+关键词）                               │
│ 3. 评估不同分块策略效果                                         │
│ 4. 准备评估数据集验证效果                                        │
```
