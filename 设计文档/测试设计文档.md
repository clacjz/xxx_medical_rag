## 5. 回归测试计划

### 5.1 功能流水线覆盖

| 流水线 | 前端操作 | 后端接口 | 测试重点 |
|--------|----------|----------|----------|
| 用户登录 | 登录页输入凭据 | POST /auth/login | Token生成、用户信息返回 |
| 文档上传 | 选择文件上传 | POST /documents/upload | 文件存储、Document记录 |
| 文档解析 | 点击处理 | POST /documents/{id}/process | 解析→分块→向量化 |
| RAG问答 | 输入问题 | POST /chat/stream | 检索→生成→流式响应 |
| 会话反馈 | 点击赞/踩 | POST /chat/sessions/{id}/messages/{msgId}/feedback | 反馈存储 |
| 知识库管理 | CRUD操作 | /collections/* | 权限检查、数据一致性 |
| 导出功能 | 导出会话 | GET /chat/sessions/{id}/export | 文件生成 |

### 5.2 端到端测试场景

#### 场景1: 完整RAG问答流程
```
1. 用户登录 → 获取Token
2. 创建知识库 → 添加文档
3. 上传文档 → 触发处理
4. 等待处理完成 → 获取分块
5. 发起问答 → 流式响应
6. 提交反馈 → 记录评价
7. 导出会话 → Markdown/PDF
```

#### 场景2: 文档管理与权限
```
1. 上传文档 → 设置权限(部门/指定人员)
2. 其他用户尝试访问 → 权限检查
3. 部门管理员访问 → 应该有权限
4. 普通用户无权限访问 → 应该拒绝
```

#### 场景3: 多知识库检索
```
1. 创建多个知识库
2. 向不同知识库添加不同文档
3. 选择多个知识库发起问答
4. 验证返回结果来自正确知识库
```

## 9. 测试代码质量规范

### 9.1 命名规范
- 测试类: `XxxServiceTest`, `XxxControllerTest`
- 测试方法: `method_Scenario_ExpectedResult`

### 9.2 测试结构
```java
@Nested
@DisplayName("功能模块测试")
class XxxTests {
    @Nested
    @DisplayName("成功场景")
    class SuccessTests { }

    @Nested
    @DisplayName("失败场景")
    class FailureTests { }
}
```

### 9.3 Mock规范
- 使用 `@Mock` 注解
- 使用 `@InjectMocks` 自动注入
- 避免过度Mock，优先使用真实对象

### 9.4 断言规范
- 使用具体断言消息
- 验证调用次数 `times(n)`
- 验证调用顺序 `InOrder`
